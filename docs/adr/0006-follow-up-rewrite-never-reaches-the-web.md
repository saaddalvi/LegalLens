# A Follow-up's rewrite never reaches the web Fallback

A Follow-up in a Contract conversation ("what about the notice period for that?") is rewritten into a standalone Query from the conversation's earlier turns before the Contract's Clauses are searched, the Corpus is searched and the Grader runs. That rewrite is built from earlier answers, which quote Clauses verbatim, so it can carry Contract text: names, amounts, addresses. The web Fallback therefore never sees it. The Fallback's web Query is built only from the user's own Queries in that Contract conversation (the current one and the earlier ones), never from answers, Clause references or Clause text.

This keeps the rule from the Contract explainer that Contract text stays between LegalLens, the model and the user's own database, and never goes to a third-party search provider. The cost is that a Follow-up whose meaning comes from an earlier *answer* rather than an earlier *Query* gets a vaguer web search. That only matters when the Corpus Verdict is not `correct`. Sending the rewrite to the web after a model-based "strip private details" pass was rejected, because a missed name or amount is a leak that cannot be taken back.
